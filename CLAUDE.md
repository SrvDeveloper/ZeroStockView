## What this is

ZeroStockView (在庫状況調査システム) is an internal inventory-survey tool. A user uploads five stock-report files exported from external systems. The app matches the rows against a configured set of product codes (品番) and stores a snapshot of per-SKU stock levels by warehouse. That snapshot is called a "survey" (調査). Surveys can be viewed, annotated with memos, exported to Excel, and charted over time. Domain requirements and sample input/output files are in `doc/` (in Japanese). Read `doc/要件概要.md` / `doc/要件定義書.md` before changing import rules.

## Architecture

**SPA served by Laravel.** `routes/web.php` defines every JSON endpoint under the `/api` prefix (session auth through the `auth` middleware; there is no `routes/api.php`). A final catch-all `Route::view('/{any}', 'app')` hands everything else to the Vue app. Auth uses Laravel session cookies plus a CSRF token, which `resources/js/app.ts` reads from a meta tag and sets on axios. Users log in with `login_id`, not email.

**Import pipeline** (`app/Services/InventoryImportService.php`) is the core of the app:
1. An `ImportSetting` (named; 1–50 `ImportTarget` product codes) selects which products to survey.
2. `CrossWalkerClient` refreshes those products and their SKUs (ASIN, TQ item/color/size) from the external product-identifier API ("CrossWalker", configured via `CROSSWALKER_*` in `config/services.php`). API failures throw `CrossWalkerException`, which renders as a JSON error response.
3. Five uploaded files are parsed, each keyed by an internal name with a Japanese display type (`FILE_TYPES`): Amazon own stock (TSV), Amazon FBA (CSV), BOSS (one CSV supplying both own-warehouse and RFC stock), TQ KEEP list → `ec_stock` (summed per SKU), and TQ stock inquiry → `free_stock`. Rows are matched to SKUs by ASIN, SKU code, or the TQ item/color/size key.
4. Inside one transaction, `Product`/`Sku` master data is copied into `Survey` → `SurveyProduct` → `SurveySku` snapshot rows with the stock columns. The uploaded files are stored on the `local` disk as `SurveyFile` records with a 30-day `expires_at`.
5. `reimport` ("rerun") replays a past survey's stored files against a different setting while keeping the original `executed_at`. It fails once the files have expired.

The `Product`/`Sku` tables are a cache of CrossWalker master data. `survey_*` tables are denormalized snapshots, so history stays stable when master data changes. Expired files are pruned by the scheduled `survey-files:prune` command (`routes/console.php`) and also opportunistically in `SurveyController::index`.

**Outputs.** `SurveyExcelExporter` writes `.xlsx` by hand (raw OOXML zipped). No spreadsheet library is installed, so keep it that way unless asked. Inventory trends (`InventoryTrendController`, `InventoryTrendCsvExporter`) aggregate `survey_skus` across surveys by date; they are not a separate data store.

**API shape.** Responses are built with API Resources or arrays that emit camelCase keys and string IDs (e.g. `SurveyResource`). TypeScript types in `resources/js/types/index.ts` and `resources/js/api/*.ts` mirror these shapes, so update both sides together.

**Frontend.** Vue 3 + Pinia (with `pinia-plugin-persistedstate`) + Vue Router + Tailwind v4/Flowbite. Pages are lazy-loaded in `resources/js/router/index.ts`. The router guard calls `auth.initialize()` (`GET /api/user`) and redirects unauthenticated users unless the route has `meta.public`. `app.ts` mounts the app first and preloads the import-settings and surveys stores behind a global loading indicator (`router/loading.ts`). Shared UI primitives are the `Base*` components in `components/ui/`; reuse them. The `@` alias resolves to `resources/js`. Vitest tests mock `vue-router` and the `@/api/*` modules with `vi.mock`, and backend tests fake CrossWalker with `Http::fake`.

UI text, validation messages, and comments are in Japanese. Match that.
