# BHR-06 データ取込画面での取込

**目的:** データ取込画面から在庫変動履歴を取り込めるようにする。取り込む前に、どの日をどう補完するかを確認してから適用する。

**依存:** BHR-04

## 作業

- データ取込画面の、Amazon 在庫のカードの下（狭い画面では取込ファイルのカードの下）に、カード「休日のBOSS在庫を補完」を足す。
  - 説明: 「BOSSの在庫変動履歴を取り込むと、在庫レポートを出力していない日のBOSS在庫を、9:00時点の値で再現します。休日前の最後の出勤日の0:00から、休日明けにレポートを出力したあとまでの履歴を出力してください。」
  - 「在庫変動履歴を選択」ボタン（CSV を1件）。選ぶと確認の API（BHR-04）を呼ぶ。
- 確認の表示（`BaseModal` か、カードの中の表示）
  - 履歴の期間、行数、処理種別ごとの行数
  - 基準の調査（日付、推定したレポートの時刻、不一致の件数）
  - 補完する日の表: 日付（曜日付き）、調査の有無（「新しく作る」／「既存の調査を更新」）、値が入る SKU 数、データなしになる SKU 数（理由ごとの件数を吹き出しで）
  - 不一致の SKU があるときは注意（`BaseAlert` の warning）に件数と、SKU・倉庫の一覧（最初の 20件と「ほか ◯件」）
  - 補完できない日があるときは、その日付と理由
  - 「補完を実行」（主ボタン）と「キャンセル」
- 実行すると適用の API を呼び、成功したら「◯日分のBOSS在庫を補完しました」とトーストを出し、補完した日の一覧（調査結果へのリンク）をカードに出す。調査一覧のストア（`surveys`）を読み直す。
- エラー（422 の検証メッセージ、それ以外の失敗）は、カードの中に `BaseAlert` で出す。
- 閲覧者にはカードを出さない（データ取込画面そのものが編集者以上）。

**実装状況（2026-10-23）:** データ取込画面に、カード「休日のBOSS在庫を補完」（`components/import/BossHistoryImportCard.vue`）と、確認・適用の API のクライアント（`api/bossInventoryHistories.ts`）を追加した。カードは、広い画面では Amazon 在庫のカードの下、狭い画面では取込ファイルのカード（とその注意・エラー）のすぐ下に出す。チケットから決めた点は次のとおり。

- 確認の表示は `BaseModal`（幅 lg）にした。データなしの SKU 数は、点線の下線を付け、マウスを重ねるかフォーカスすると理由ごとの件数を吹き出しで出す。
- 不一致の一覧には、照合で合わない SKU・倉庫に加えて、つながりの切れ目・マイナスでデータなしになる SKU・倉庫も出す（BHR-04 の `mismatches`）。後者は「SKU（倉庫・理由）」と理由を添える。
- 履歴の期間とレポートの時刻は、ほかの画面と同じくブラウザのタイムゾーンで表示する。
- 適用に失敗したときは、確認の表示を閉じてカードの中にエラーを出す（選び直して確認からやり直す）。補完した日の一覧は、調査結果へのリンク（日付と曜日）にする。
