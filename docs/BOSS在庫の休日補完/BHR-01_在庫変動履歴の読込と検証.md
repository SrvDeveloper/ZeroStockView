# BHR-01 在庫変動履歴の読込と検証

**目的:** BOSS の「在庫変動履歴」CSV を読み込み、再現の計算（BHR-02）に使える形にする。ファイルの形式と、行どうしのつながりを検証する。

**依存:** なし

## 作業

- `app/Services/BossInventoryHistoryParser.php`（新規）を作る。入力は `UploadedFile`、出力は読み込んだ行の一覧と、検証の結果。
- 文字コードは CP932 と UTF-8（BOM あり・なし）を受け付ける。既存の CSV 読込（`InventoryImportService::rows()`）と同じ扱いにし、共通化できるなら共通化する。
- 必要な列: `処理日時`、`処理種別`、`処理番号`、`SKUコード`、`倉庫`、`変動前実在庫`、`変動後実在庫`、`変動前引当済`、`変動後引当済`。ほかの列は使わない（`変動後実在庫 - 変動後引当済` は、計算と一致するかの確認にだけ使う）。
  - 列が足りない、日時が読めない（`Y/m/d H:i:s`）、数量が整数でない行は、ファイル名と行番号を付けたエラーにする（`ValidationException`、既存の取込のメッセージにならう）。
- 倉庫は `自社倉庫` と `RFC倉庫` だけを使い、ほかの倉庫の行は読み飛ばす。
- 行を SKU・倉庫ごとにまとめ、処理日時の順に並べる。同じ秒の行は、変動前の値が直前の行の変動後の値とつながる順に並べる。つながる行が見つからなければ `処理番号` の順にする。
- 検証の結果として、次を返す。
  - 期間（最初と最後の処理日時）、行数、SKU・倉庫の数、処理種別ごとの行数
  - **つながりの切れ目**: 並べたあと、ある行の「変動前の実在庫 − 引当済」が、直前の行の「変動後の実在庫 − 引当済」と違う箇所（SKU・倉庫と日時）。実在庫・引当済それぞれだけが違い、差が一致している箇所は切れ目に数えない（検証で見た、出荷が履歴に出ない経路のため）
  - **マイナスの値**: 「変動前／変動後の実在庫 − 引当済」がマイナスの行
- BOSS の在庫レポート・KEEP一覧表・在庫一覧照会表と取り違えないよう、ヘッダーで判別する関数（`isInventoryHistory()`）も用意する。既存のデータ取込（`classifyFiles()`）では、この種類を受け付けない（取込は BHR-04 の別の API で行う）。

## 対象ファイル

- `src/app/Services/BossInventoryHistoryParser.php`（新規）
- `src/tests/Unit/BossInventoryHistoryParserTest.php` または `tests/Feature/`（新規）。架空のデータの CSV をテストの中で作る

## 完了条件

- PHPUnit で次を確認する。
  - CP932・UTF-8 の読込、必要な列の不足、日時・数量の誤りのエラー
  - 自社倉庫・RFC倉庫以外の行を読み飛ばすこと
  - 同じ秒に複数の行があるときの並べ方（つながりで決まる場合、決まらず処理番号で並べる場合）
  - つながりの切れ目の検出（実在庫 − 引当済が切れる場合は数え、実在庫・引当済が同じ数だけずれる場合は数えない）
  - マイナスの値の検出
  - データ取込（`POST /api/surveys`）にこのファイルを添付すると、種類を判定できないエラーになること（今の動作のまま）
- Pint が通る。
