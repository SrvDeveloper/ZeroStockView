## 要望1 API仕様書の更新

**方針（2026-10-21 確定）:** `doc/外部公開API仕様書.md` を、依頼者が Mall Insight に渡す。

- 仕様書は性能改善（PERF-13 まで）を反映した後の動きを書いたもの。本番にはまだ反映していない（要望対応が終わってから反映する予定）。渡すときに、本番反映の日からの動きであることを伝える。
- 要望2〜7で仕様書が変わるので、渡すのはすべての対応が決まった後にまとめて1回とする。
- 渡す前に、改訂履歴と、調査履歴を最新500件（約1年4か月分）まで残すことを追記する。

**根拠になった事実**

- Mall Insight が「実際の動き」として挙げた、期間の上限31日と `validation.exists` の文言は、2026-10-02 の「本番適用」コミット（`1d723b9`）の時点のコードの動き。main では、上限は365日（`8db4cc5` から）、品番の入力エラーは日本語の独自メッセージ（`1de07b8` から）。
- main では、調査の無い日の Amazon だけの行は返さない（PERF-13）。`brand`・`category`・`size` は常に文字列。

## 要望2 調査の対象外の品番

**方針（2026-10-21 確定。Mall Insight も了承）**

1. 取込のたびに CrossWalker から有効な全品番を取得し、自動で在庫調査の対象にする。
   - CrossWalker で無効な品番は対象にしない（SKUは今も有効なものだけを対象にしている）。
   - どの品番グループにも入っていない品番は、画面では「グループなし」として表示する。品番グループは、画面で絞り込むための分類として残す。
   - 要望書の53品番・287 SKU（自社ブランド13品番・仕入商材40品番）は、CrossWalker で有効なので、すべて対象に入る。
   - 対象外の品番の一覧は Mall Insight に渡さない。対象を広げる前の日に、さかのぼって行を返すことはしない。
2. 在庫0と null の扱いを改める。0は「在庫数が0と確認できた」ことだけを表し、在庫数が無い・分からないときは null とする。

   | 区分 | ファイルを取り込む前 | 取り込んだファイルに載っている | 取り込んだファイルに載っていない |
   | --- | --- | --- | --- |
   | BOSS（自社倉庫・RFC倉庫） | null | ファイルの値（0を含む） | null（今は0） |
   | フリー在庫（在庫一覧照会表） | null | ファイルの値（0を含む） | null（今は0） |
   | ECストック（KEEP一覧表） | null | キープの数 | 0（キープが無い。今と同じ） |
   | Amazon（自社・FBA） | null | 取得した値（レポートに無ければ0） | 子ASINの無いSKUは null（今と同じ） |

   - 要件定義書の「取込済みファイル内で該当SKUの在庫がない場合は0として扱う」を書き換える。
   - 画面では、ファイルに載っていない区分を「取込待ち」ではない表示（「データなし」など）にする必要がある。
   - 変える日より前の調査は、0のまま残す。
   - Mall Insight が求めた「切り替えた日に、どのファイルにも載っていなかったSKUの一覧」は、この扱いにより不要とした。
3. 子ASINの無いSKUの Amazon の在庫は、Amazonで販売していないので数値が無く、null のままとする（0にしない）。

**根拠になった事実**

- 対象の品番は、今は品番グループ（1グループ最大50品番）の設定で決まる。
- `doc/取込データサンプル` の見本（9/11時点）では、BOSSは登録されている全SKU（1,541 SKU × 自社倉庫・RFC倉庫、うち2,245行が実在庫0）を載せていた。在庫一覧照会表も、可能在庫数0の行を載せていた（3,348行のうち1,059行）。KEEP一覧表はキープの伝票の一覧。
- 同じ見本で、仕入商材40品番はすべてBOSSに載っていた。自社13品番のうち `flw-002` だけが載っていなかった（見本が古いので、最新のファイルでの確認が必要）。
- 対象を広げても、データ量は困る量ではない（CrossWalker で有効なSKUは要望書の時点で919件。1,512 SKU・500品番でも、調査SKUの行は500件分で約75万行・約300 MB の見込み）。全品番・365日のCSVや外部APIの出力だけは、約20秒・約100 MBの見込みで、本番のタイムアウトの確認が必要。
- 在庫推移の画面は、品番の合計を出すときに、子ASINの無いSKUのAmazon在庫を0として足している。APIとCSVは null のまま返している。

**残っていること**

- CrossWalker に無いとされた9件のSKU（`eb23-50-cry` など）が、本番の CrossWalker にあるかを確認して、Mall Insight に知らせる。ZeroStockView は独自のSKUコードを持たず、すべて CrossWalker から取得している（手元のDBでは、2026-10-20 の同期で取得した有効なSKUとして入っている）。
- 切り替える日を Mall Insight に知らせる。

## 要望4 Amazon の在庫数が null になる理由の区別

要望2の確認の中で、次のように回答した（Mall Insight の返答待ち）。

- 要望2の対応後は、返すSKUはすべて CrossWalker のSKUになるので、Amazon の null が「Amazonで販売していない」ためかどうかは、CrossWalker の子ASINの有無で判断できる。行に理由の項目は追加しない。
- 「まだ取り込んでいない」かどうかは、要望3の取込状況のAPIで分かるようにする予定。
