# セキュリティ調査

調査日: 2026-10-20。Laravel/Vueのコード、ルート、設定、ロック済み依存関係を確認した。実環境への侵入試験や取込データの変更はしていない。「脆弱性が存在しない」ことを証明する調査ではない。

## 対策が必要な事項

### 1. ログイン試行に回数制限がない（優先度: 高）

`src/routes/web.php` の `POST /api/login` は共通の `web` に加えて `guest` ミドルウェアを使うが、`throttle` や `RateLimiter` を設定していない。`src/app/Http/Controllers/Api/AuthController.php` は失敗時も認証処理を実行し続ける。ログインIDとパスワードの連続試行をアプリ側で抑止できない。外部APIには `throttle:60,1` が設定されており、ログインだけ制限がないことも確認した。

**修正方針:** IPアドレスとログインIDを組み合わせた失敗回数制限を設け、成功時にカウントを解除する。共有IPからの正当な利用を妨げにくい閾値とし、429応答と解除条件をテストする。リバースプロキシ配下では信頼するプロキシの設定を確認する。

**対応状況（2026-10-21）:** 対応済み。依頼者の方針で、ログインIDごとのロックにした（`app/Services/LoginLockout.php`）。

- 最初の失敗から15分以内に5回失敗すると、そのログインIDを1時間ロックし（2026-10-21 に依頼で15分から1時間に変更）、429とロック解除の時刻・特権管理者への依頼を案内するメッセージを返す。ロック中は正しいパスワードでもログインさせない。ログインに成功すると失敗の回数を消す。ロックしたときはログに記録する。
- ログインIDは大文字・小文字を区別せずに数える。存在しないログインIDも同じように数えてロックし、応答からアカウントの有無が分からないようにした。
- 特権管理者は、ユーザー管理の画面でロック中のユーザーを確認し、ロックを解除できる（`POST /api/users/{user}/unlock`）。
- 失敗の回数とロックはキャッシュ（本番の既定は `database`）に保存する。キャッシュを消すとロックも外れる。
- 残る点: IPアドレスごとの制限は入れていないため、1つのパスワードを多数のログインIDに試す攻撃は、ログインIDごとの5回までは止められない。また、第三者が他人のログインIDをわざと失敗させてロックし、1時間ログインを妨げることができる（特権管理者が解除できる）。リバースプロキシ配下では、ログに記録するIPアドレスのために信頼するプロキシの設定を確認する。
- IPアドレスごとの制限と社外からのアクセスの遮断は、依頼者の判断で入れない（2026-10-21）。社内の利用者は全員が同じ固定のIPアドレスから使うため、IPアドレスごとの制限では1人の失敗で全員がログインできなくなる。社外からのアクセスを遮断すると利便性が下がる。

### 2. パスワード変更・管理者による再設定後も既存セッションが残る（優先度: 中）

`AuthController::changePassword()` はパスワードを保存するだけで、他端末のセッションを失効させない。`UserController::update()` の `invalidateSessions()` は権限変更時だけ呼ばれ、パスワードのみ変更した場合は呼ばれない。対象ルートにセッションのパスワードハッシュを照合するミドルウェアもない。したがって、漏えいしたセッションCookieをパスワード変更で無効化できない。

**修正方針:** 本人による変更と管理者による再設定の両方で、対象ユーザーの既存セッションを失効させる。本人の現在のセッションを継続するか再ログインさせるかを決め、複数端末のテストで確認する。セッション保存先がDB以外の場合の処理も明示する。

### 3. 在庫履歴CSVの文字列を表計算ソフトが式として実行する可能性（優先度: 中、入力条件あり）

`InventoryTrendCsvExporter::rows()` はCrossWalker由来の品番・ブランド・カテゴリ・SKU・サイズをCSVの文字列列に入れる。`writeRow()` は `fputcsv()` のみで、先頭が `=` などの値を式として扱われないようにする処理がない。これらの元データを攻撃者が変更でき、受信者がCSVを表計算ソフトで開く場合に成立する。通常の画面表示はVueの文字列展開で、調査結果のXLSXは `inlineStr` セルとして生成しているため、この指摘はCSV出力に限定する。CSV式注入の条件は [OWASPの説明](https://community.owasp.org/attacks/CSV_Injection) と一致する。

**修正方針:** 表計算ソフト向けCSVの文字列列について、式として解釈される先頭文字を処理する。機械取込向けの外部APIと値が異なる可能性があるため、CSVの利用者と必要な互換性を確認してから方式を選ぶ。`=`, `+`, `-`, `@` と日本語環境の全角文字をテストする。

## 運用環境で確認する事項

- `src/.env.example` はローカル開発向けに `APP_DEBUG=true` で、`SESSION_SECURE_COOKIE` の値を指定していない。実運用の `APP_DEBUG=false`、HTTPS、Secure Cookie、信頼するプロキシの設定を確認する。環境ファイルの値だけでは、公開環境の設定は判断できない。
- アプリ内にはCSP、`frame-ancestors` などのヘッダー設定が見当たらない。WebサーバーやCDNで付与している可能性があるため、実際のHTTP応答で確認する。

## 確認できた防御と範囲

- 業務APIにはサーバー側の `auth` と `role` ミドルウェアがあり、既存の `RoleAuthorizationTest` と `ExternalInventoryApiTest` は17件・285アサーションすべて成功した。
- 外部日次APIはAPIキーのハッシュ照合、許可IP/CIDR、分単位のリクエスト制限を持つ。アップロードはCSV/TXTとサイズを検証し、保存先は非公開ディスク。調査結果XLSXの文字列はXMLエスケープした `inlineStr` セルとして書き出している。
- 画面側に `v-html` や `innerHTML` によるデータ描画は見当たらず、確認したDBアクセスはEloquentのクエリビルダーを使用している。これは全経路の安全を保証するものではない。

## 依存パッケージの監査結果と制約

`composer.lock` は Laravel `v13.31.0`、`package-lock.json` は Axios `1.20.0`。2026-10-19公開のLaravelの[認証回避](https://github.com/laravel/framework/security/advisories/GHSA-f9x3-7vq9-cph6)と[意図しないデータ削除](https://github.com/laravel/framework/security/advisories/GHSA-5wcm-3v2w-8362)、2026-09-10公開の[デバッグ画面XSS](https://github.com/laravel/framework/security/advisories/GHSA-jh5r-qr3c-85q8)については、ロック済み版が各修正版以降であることを手動確認した。

`composer audit --locked` と `npm audit --package-lock-only` は、監査サーバーへのDNS名前解決が失敗したため完了していない。全依存関係の既知脆弱性については未判定であり、ネットワークが使える環境で両コマンドを再実行する。
