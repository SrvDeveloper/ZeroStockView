# UM-03 ユーザー管理APIとセッション失効

**目的:** 特権管理者だけがユーザーを管理でき、権限変更後に旧セッションを使えないようにする。

**依存:** UM-01

## 作業

- 特権管理者専用のユーザー一覧・作成・編集・削除APIを追加する。対象項目はログインID、パスワード、ロールのみとする。
- ログインIDの必須・一意性、パスワードの入力条件、ロール値を検証する。編集時の空欄パスワードは変更しない。応答にはパスワードやハッシュを含めない。
- 自分自身の削除と、最後の特権管理者の削除・降格を拒否する。競合する同時更新でも管理者が0人にならないようにする。
- ロール変更時は対象ユーザーの全セッションを即時無効化する。自分のロールを変更した場合も現在のセッションを終了する。ユーザー削除時も対象の全セッションを無効化する。
- `SESSION_DRIVER=database` の現行設定と、実際の認証ガード・セッション保存方式を確認し、失効したセッションが次のリクエストで401になることをテストする。ロール変更を伴わないログインID・パスワード更新は、この即時失効要件の対象外とする。

## 対象の目安

`src/app/Http/Controllers/Api/`、`src/app/Http/Requests/`、`src/routes/web.php`、必要なセッション失効処理、`src/tests/Feature/`。

## 完了条件

- 編集者・閲覧者が管理APIを直接呼んでも403となる。
- 作成、更新、パスワード再設定、削除の正常系・入力エラーを確認できる。
- 最後の特権管理者が残り、ロール変更・削除されたユーザーの複数セッションが即時に無効となる。
