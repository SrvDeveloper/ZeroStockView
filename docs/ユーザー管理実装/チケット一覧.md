## 進め方と境界

- `UM-02`、`UM-03`、`UM-04` は `UM-01` の後に進められる。`UM-05`、`UM-06`、`UM-07` はそれぞれの依存先が整った後に進める。
- APIの許可・拒否は `UM-02` と `UM-03` が担当し、画面側の非表示・導線は `UM-04`〜`UM-07` が担当する。画面の非表示だけを認可の代わりにしない。
- 操作マニュアルは全ロール、連携ステータスは編集者以上。公開の外部在庫APIは画面ユーザーのロール認可の対象外。
- 既存の未コミット変更は保護する。各チケットの変更範囲を確認し、無関係なファイルを整形しない。

## 共通の完了条件

- 許可された操作が成功し、権限外の直接APIアクセスは403で終了して状態を変更しない。認証が切れたアクセスは401とする。
- PHPの変更では関連するPHPUnitを実行し、`vendor/bin/pint --dirty --format agent` で触ったPHPを整える。フロントエンドの変更では関連するVitestと型・Lintの確認を行う。
- 最終チケットで `src/` から `composer test`、`npm run check`、必要に応じて `npm run build` を実行し、`git diff --check` と差分を確認する。
