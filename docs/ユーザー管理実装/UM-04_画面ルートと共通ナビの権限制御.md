# UM-04 画面ルートと共通ナビの権限制御

**目的:** ロールに応じた開始画面、メニュー、直URLアクセス制限を整える。

**依存:** UM-01

## 作業

- フロントエンドの認証ストアにロールを保持し、ログイン直後と再読み込み後に現在のロールを取得する。
- ルートごとに必要なロールを定義する。未ログインはログインへ、ログイン済みで権限外の画面は利用可能な開始画面へ案内する。
- 閲覧者の開始画面を在庫調査履歴とする。編集者と特権管理者の開始画面はデータ取込とする。
- サイドバーに閲覧者は調査履歴・在庫推移・操作マニュアル、編集者はそれらと取込・品番グループ、特権管理者は全画面とユーザー管理を表示する。
- 連携ステータスは編集者以上に表示する。ログアウト・自分のパスワード変更は全ロールで使えるようにする。
- 404画面など、固定の遷移先が権限外にならないようにする。

## 対象の目安

`src/resources/js/stores/auth.ts`、`src/resources/js/router/`、`src/resources/js/constants/navigation.ts`、`src/resources/js/components/AppSidebar.vue`、`src/resources/js/components/AppTopBar.vue`、関連するVitest。

## 完了条件

- 3ロールのログイン・再読み込み・ログアウト・直URLアクセスで正しい画面とメニューになる。
- 閲覧者はマニュアルと自分のパスワード変更を利用でき、連携ステータスを表示しない。編集者には連携ステータスが表示される。
- 認可はAPI側でも実施され、ルートガードだけに依存しない。
