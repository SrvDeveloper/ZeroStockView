# ユーザー管理・権限管理 改修要件

実装の作業順と個別の完了条件は[チケット一覧](チケット一覧.md)を参照。

## 1. 目的と対象

ログインユーザーを管理し、役割に応じて画面と API の操作を制限する。権限は「特権管理者」「編集者」「閲覧者」の3種類とする。

この文書は改修範囲と受入条件の整理であり、実装は含まない。指定された権限と追加の決定事項を「確定要件」、詳細が未指定のものを「設計案」「確認事項」として区別する。

## 2. 確定要件

| 機能 | 閲覧者 | 編集者 | 特権管理者 |
| --- | --- | --- | --- |
| 在庫調査履歴・調査結果の閲覧 | 可 | 可 | 可 |
| 在庫推移の閲覧 | 可 | 可 | 可 |
| 調査結果Excel・在庫推移CSVの出力 | 可 | 可 | 可 |
| 元の取込ファイル・ZIPのダウンロード | 可 | 可 | 可 |
| データ取込 | 不可 | 可 | 可 |
| 保存ファイルでの再照合 | 不可 | 可 | 可 |
| 品番グループの追加・編集 | 不可 | 可 | 可 |
| 品番グループの削除 | 不可 | 不可 | 可 |
| Amazon在庫の手動取込 | 不可 | 不可 | 可 |
| 連携ステータスの閲覧 | 不可 | 可 | 可 |
| 操作マニュアルの閲覧 | 可 | 可 | 可 |
| 上記以外の業務操作 | 不可 | 不可 | 可 |
| ユーザー管理・権限変更 | 不可 | 不可 | 可 |

- 閲覧者は在庫調査履歴と在庫推移の閲覧、調査結果のファイル出力、元の取込ファイル・ZIPのダウンロード、および操作マニュアルの閲覧が可能とする。
- 編集者は閲覧者の権限に加え、データ取込・再照合と品番グループの追加・編集が可能とする。削除はできない。
- 特権管理者はすべての機能を利用できる。
- ロール名は画面上では日本語で表示し、保存値は固定の識別子を使う。個別権限の組み合わせや第4のロールは今回の対象外とする。

## 3. 現状と改修箇所

現状は `users` テーブルにログインIDとパスワードがあり、セッション認証を利用している。ロール列、ユーザー管理画面、ロール別のAPI制限はない。ログイン済みユーザーはすべての業務APIを呼び出せる。

| 領域 | 必要な改修 |
| --- | --- |
| DB・モデル | ユーザーにロールを保持し、既存ユーザーの移行方針を定める。 |
| 認証 | ログイン応答と現在ユーザー取得APIでロールを返す。 |
| API認可 | 画面表示とは独立に、各API操作でロールを検査する。未ログインは認証エラー、権限不足は403とする。 |
| ユーザー管理 | 特権管理者用の一覧・作成・編集・削除、およびロール設定を追加する。 |
| 画面 | ロールに応じてメニュー、操作ボタン、画面遷移を制御する。直URLアクセスも制限する。 |
| テスト | 各ロールの許可・拒否、ユーザー管理、既存ユーザー移行を検証する。 |

対象の既存画面は、データ取込、在庫調査履歴・結果、在庫推移、品番グループ、ファイル管理、API連携設定である。既存APIは主に `src/routes/web.php` の `/api/*` に定義されている。公開の外部在庫API `/api/v1/inventory/daily` は別のAPIキー認証を使っており、今回の画面ユーザーロールとは切り離して扱う。

## 4. 操作別の認可方針

以下は確定要件を既存機能に当てはめた認可方針。

| 操作・API群 | 最低ロール | 理由・補足 |
| --- | --- | --- |
| `GET /api/surveys`、`GET /api/surveys/{id}` | 閲覧者 | 在庫調査履歴・結果の閲覧。 |
| `GET /api/inventory-trends`、`GET /api/inventory-trends/products` | 閲覧者 | 在庫推移の閲覧。 |
| `GET /api/surveys/{id}/export`、`GET /api/inventory-trends/export` | 閲覧者 | 調査結果Excel・在庫推移CSVのファイル出力。 |
| `GET /api/survey-files/{id}/download`、`GET /api/surveys/{id}/files/download` | 閲覧者 | 元の取込ファイルと一括ZIPのダウンロード。 |
| `POST /api/surveys` | 編集者 | データ取込。 |
| `POST /api/surveys/{id}/rerun` | 編集者 | 保存ファイルでの再照合。下記の説明を参照。 |
| `GET /api/import-settings`、`POST /api/import-settings`、`PUT /api/import-settings/{id}` | 編集者 | 品番グループの参照・追加・編集。 |
| `GET /api/crosswalker/items` | 編集者 | 品番グループ編集時の商品検索。 |
| `DELETE /api/import-settings/{id}` | 特権管理者 | 品番グループの削除。 |
| 調査履歴・取込ファイルの削除、調査結果のメモ変更 | 特権管理者 | 編集者に明示された操作以外の変更。 |
| `GET /api/integrations/status`、Amazon在庫取込履歴の参照 | 編集者 | 連携ステータスの表示に必要な読み取り。 |
| `POST /api/amazon-inventory-imports` | 特権管理者 | Amazon在庫の手動取込。 |
| ファイル管理画面、取込ファイルの削除、API連携設定、APIキー再発行 | 特権管理者 | 管理操作。ファイルのダウンロード権限は上記のとおり。 |
| ログイン、ログアウト、自分のパスワード変更 | 全ロール | アカウントを使うための共通操作とする案。 |

ユーザー管理APIは特権管理者だけに公開する。クライアントでボタンを隠すだけで済ませず、直接HTTPリクエストを送った場合も同じ権限判定を行う。

### 「再照合」の意味

現在の調査結果画面にある「保存ファイルで再照合」を指す。過去の調査に保存されている取込ファイルを読み直し、**現在の品番グループの対象品番**と照合して、同じ日の調査結果を更新する。新しいファイルをアップロードする操作ではない。初回取込日時は変えず、保存ファイルがない場合は実行できない。編集者と特権管理者が実行できる。

## 5. ユーザー管理の実装案

- 一覧にはログインID、ロール、操作を表示する。パスワードやハッシュは返さない。
- 作成時はログインID、初期パスワード、ロールを入力する。ログインIDの重複と入力値を検証する。
- 編集時はログインIDとロールを変更でき、パスワードは入力した場合だけ再設定する。
- 削除前に対象を確認する。自分自身の削除と最後の特権管理者の削除・降格は拒否し、管理不能な状態を防ぐ。
- パスワードは既存のハッシュ化方式を利用し、API応答・ログ・画面に平文を再表示しない。
- ユーザー管理項目はログインID・パスワード・ロールに限定し、表示名、メールアドレス、有効/無効状態、操作履歴は追加しない。
- ロールを変更した場合は、対象ユーザーの全セッションを変更時に無効化する。対象が自分自身なら自分のセッションも終了する。ユーザー削除時も対象ユーザーの全セッションを無効化する。終了済みセッションでの次のリクエストは認証エラーとする。

## 6. 画面の実装案

- 閲覧者の開始画面は在庫調査履歴とする。メニューには在庫調査履歴、在庫推移、操作マニュアルを表示する。調査結果Excel・在庫推移CSVの出力操作も表示する。
- 閲覧者がファイル管理画面を開かなくても、在庫調査履歴または調査結果から元の取込ファイルと一括ZIPをダウンロードできる導線を設ける。ファイルの削除操作は表示しない。
- 編集者には上記に加え、データ取込、再照合、品番グループ、連携ステータスを表示する。品番グループの削除操作は表示しない。
- 特権管理者には現行の全メニューとユーザー管理を表示する。
- 権限外のURLを直接開いた場合は、利用可能な画面へ案内する。ログイン済みユーザーをログイン画面から戻す際も、そのユーザーが利用できる開始画面へ遷移する。
- 在庫調査履歴の削除ボタン、調査結果のメモ編集など、共通画面にある変更操作もロールに応じて非表示または読み取り専用にする。
- アカウントメニューのログアウトと自分のパスワード変更は全ロールに残す案とする。

## 7. 移行・受入条件

### 移行

- 既存ユーザーを失効させず、移行時に特権管理者として扱う案とする。移行後に明示的にロールを変更できるようにする。
- 初期管理者を作る既存のシーダーとユーザーファクトリーも新しいロールに対応させる。
- 既存のログインID、パスワード、セッション認証と外部公開APIの認証方式は維持する。

### 受入条件

1. 各ロールでログインしたとき、許可された画面・操作だけを利用できる。
2. 権限外のAPIに直接アクセスすると403が返り、DBやファイルが変更されない。
3. 編集者は取込・再照合と品番グループの作成・編集に成功し、品番グループ削除には失敗する。
4. 閲覧者は在庫調査履歴・結果と在庫推移を閲覧でき、取込・再照合・編集・削除には失敗する。
5. 閲覧者は調査結果Excelと在庫推移CSVを出力でき、元の取込ファイルと一括ZIPをダウンロードできる。すべてのロールで操作マニュアルを閲覧でき、編集者以上で連携ステータスを閲覧できる。
6. 特権管理者はAmazon在庫の手動取込を含む全業務機能とユーザー管理を利用できる。
7. ユーザーの作成・編集・削除で入力検証が働き、最後の特権管理者を失わない。権限変更・削除されたユーザーの既存セッションは直ちに無効となる。
8. 既存ユーザーは移行後もログインできる。
9. PHPUnitの権限テストと、メニュー・ルート・操作表示に関するVitestを追加し、既存の `composer test` と `npm run check` を通す。
