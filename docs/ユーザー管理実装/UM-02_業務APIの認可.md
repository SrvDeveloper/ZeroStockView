# UM-02 業務APIの認可

**目的:** 既存の全業務APIで、[改修要件](README.md)の権限表をサーバー側で強制する。

**依存:** UM-01

## 作業

- 共通のロール判定を用意し、`src/routes/web.php` の認証必須APIを操作単位で分類する。未認証は401、認証済みで権限不足は403とする。
- 閲覧者には調査履歴・結果と在庫推移の取得、結果Excel・推移CSVの出力、元の取込ファイルと一括ZIPのダウンロードを許可する。
- 編集者には上記に加え、調査の取込・保存ファイルでの再照合、品番グループの参照・作成・編集、CrossWalker商品検索、連携ステータスとAmazon取込履歴の参照を許可する。
- 特権管理者には上記に加え、品番グループ・調査・取込ファイルの削除、調査メモ変更、ファイル管理、API連携設定・キー再発行、Amazon在庫の手動取込を許可する。
- `/api/v1/inventory/daily` は既存のAPIキー認証を維持する。`/api/user`、ログアウト、自分のパスワード変更はログイン済みの全ロールに許可する。
- モデル結合やファイルダウンロードの前に認可されるようにし、拒否時は副作用がないことを確認する。

## 対象の目安

`src/routes/web.php`、`src/app/Http/Middleware/`、`src/bootstrap/app.php`、必要な認可ポリシー、`src/tests/Feature/`。

## 完了条件

- 全業務APIに許可ロールが割り当てられ、未割当の認証済みAPIがない。
- 各ロールの許可・拒否をFeatureテストで確認する。特に編集者による再照合の許可と削除・Amazon手動取込の拒否、閲覧者による再照合の拒否とファイル出力・ダウンロードの許可を検証する。
- 権限不足時にDB・保存ファイルが変更されず、公開APIの認証方式が変わらない。
