# 操作マニュアル整備

操作マニュアル（`src/resources/js/pages/ManualPage.vue`）を、現在のシステムの機能に合わせて完成させるための計画とチケット。チケット番号は `MAN-xx` で管理する。

## 方針（2026-10-19 依頼者確認済み）

- 対象はシステム自体の操作説明。外部システム（BOSS・ターコイズ）からのファイル取得の手順は、文章の誤りを直すだけにする。
- 「よくある質問」は作らない（節ごと削除する）。
- 画面キャプチャは入れない。画像の枠も置かない。必要な箇所には依頼者が後から挿入する。外部システムの手順にある既存の画像は残す。
- ダウンロードしたファイルのリネームのヒントは削除する。取込ファイルの種類はファイルの中身（1 行目の見出し）で判別するため、名前を変える必要はない。
- 画面の名前・ボタン・表示文言は、現在の画面（コード）と一字一句合わせる。権限によって使えない操作は、その旨を書き添える（[ユーザー管理の要件](../ユーザー管理実装/README.md)の権限表に従う）。
- 既存の節 ID（`introduction`、`basic-operation-boss`、`basic-operation-ec`、`basic-operation-free`、`notes`）は変えない。後から画像を入れる場所や目次のリンクを保つため。

## チケット一覧

### MAN-01 構成の整理と既存部分の修正

- 目次を上の完成形の順に組み直す（未作成の節はチケットごとに足す）。「よくある質問」を削除する。
- 外部システムの 3 手順の誤りを直す。手順の見出しの写し間違い（例: フリー在庫の手順の「ECストック倉庫のKEEP一覧表を出力」）、画像の説明文の写し間違い、節の見出しの表記を揃える。リネームのヒント 3 か所を削除する。
- 「はじめに」を書き直す。システムの概要（何を調べるシステムか）、1日の流れ（ファイル準備 → データ取込 → 結果の確認、Amazon在庫は毎朝自動取得）、権限ごとにできることの表、品番を CrossWalker に事前登録しておくこと。

**実装状況（2026-10-20）:** 実装済み。外部システムの手順で直したのは、フリー在庫の手順 2・3 の見出し（KEEP一覧表の写し間違い）と、画像の説明文 3 か所（02-2・03-3・04-3）だけ。それ以外の文言は元のまま残した。「Amazon在庫取得」と「注意事項」は、MAN-02・MAN-05 で書き直すまで、内容を変えずに置き場所だけ移した。

### MAN-02 データ取込と Amazon 在庫の取得

- データ取込: 3 種類のファイルの添付（1〜3 件、種類は中身で判別）、取込の実行、同じ日の追加取込で同じ調査が更新されること、未添付の種類は取込待ちになること、取込対象は全品番グループの品番であること。編集者以上の操作であること。
- Amazon在庫の取得: 毎朝 9:00 の自動取得、データ取込画面での状態と履歴の見方、手動取得（特権管理者のみ）、取得が成功するとその日の調査に反映されること（調査がなければ Amazon 在庫だけの調査が作られる）、取込待ち・一部SKU未取得の意味。

**実装状況（2026-10-20）:** 実装済み。「データ取込」の節を新設し、「Amazon在庫取得」の節を「Amazon在庫の取得」に書き直した。Amazon在庫の取り直しは同じ日のうちに行う必要があること（翌日の取得は前の日の調査に反映されない）も書き添えた。

### MAN-03 在庫調査履歴と在庫調査結果

- 在庫調査履歴: カレンダーとリストの切り替え、日の選択と詳細欄（取込ファイルの状態とダウンロード、一括ダウンロード、結果を開く、Excel出力）、削除（特権管理者のみ）。
- 在庫調査結果: 状態のまとめ、在庫表の見方（倉庫・総数・取込待ちの「—」・確定した「0」・全倉庫ゼロ／一部ゼロの表示、Ctrl＋マウスで内訳）、品番グループの切り替え、絞込、メモ（特権管理者のみ編集）、Excel出力（全件・絞込結果）、再読込、保存ファイルで再照合（編集者以上。使える場面と、旧方式の調査では使えないこと）、取込ファイルの一括ダウンロード。

**実装状況（2026-10-20）:** 実装済み。「在庫調査履歴」「在庫調査結果」の節を追加した。表示と意味の 2 列の表は共通部品 `ManualTermTable.vue` にまとめ、MAN-02 の Amazon の表もこれに置き換えた。あわせて、MAN-02 で「一部未取得の SKU は『—』」と書いていた誤りを「取込待ち」の札に直した。

### MAN-04 在庫推移

- 対象品番・在庫区分・表示期間・期間の選び方、品番全体（倉庫別の積み上げ、欠品SKU数、未確定の印、ツールチップ）と SKU別（ミニグラフ）、SKU別サマリーの見方、日次在庫のCSV出力（選択品番・全品番）。

**実装状況（2026-10-20）:** 実装済み。「在庫推移」の節を追加した。在庫区分と日次在庫CSVの列は表にまとめ、CSVの空欄（未確定）と 0 の違いをヒントとして書き添えた。

### MAN-05 設定画面と注意事項

- 品番グループ: 一覧、作成・編集（品番の検索と追加、並び順）、削除（特権管理者のみ）、取込対象は全グループの品番の和集合であること。
- ファイル管理（特権管理者のみ）: 保存期限（30日）、ダウンロード、削除。
- API連携設定（特権管理者のみ）: 外部APIの有効・無効、APIキーの再発行（表示は一度だけ）、許可するIPアドレス。
- ユーザー管理（特権管理者のみ）: 追加・編集・パスワード再設定・削除、権限変更でセッションが終了すること、最後の特権管理者の保護。
- 注意事項: 取込ファイルの保存期限、取込待ちと 0 の違い、Amazon在庫の反映のタイミング、旧方式（5ファイル）の調査の扱いなど、操作時に間違えやすい点。

**実装状況（2026-10-20）:** 実装済み。設定画面 4 節を追加し、注意事項のひな形を書き直した。注意事項には、チケットの項目に加えて、調査の日付（日本時間で取込を実行した日）と連携ステータスの見方を入れた。ユーザー管理の節には、全員が使える「パスワード変更」の場所も書き添えた。

## デザイン刷新（MANUI）

MAN-01〜05 で書いた本文を、デザイン案（Design キャンバス「操作マニュアル デザイン案」の A 案・B 案・スマホ案）の見た目と構成に作り替える。チケット番号は `MANUI-xx`。

### 決定事項（2026-10-20 依頼者確認済み）

- 節のページは B 案にする。1 節＝1 ページとし、左に章ごとの目次、中央に本文、右に「このページの内容」を置く。
- 入口ページとして A 案（ホーム）を作る。`/manual` はホームを表示する。
- 検索を入れる。マニュアルの中をブラウザだけで検索し、サーバー側は変えない。
- 画面の部分的な再現図（押す場所を黄色の枠で示す図）は、場所が分かりにくい操作に絞って入れる（MANUI-05）。ほかの節は、ボタン名やメニュー名の札だけにする。理由：再現図は画面を変えるたびに直す必要があり、依頼者が後から画面キャプチャを入れる箇所とも重なるため。
- 本文の内容（MAN-01〜05 で書いた説明）、外部システムの手順の画像、節の ID は変えない。

### MANUI-01 節ごとのページとレイアウトの土台

- ルート：`/manual`（ホーム。MANUI-03 までは「はじめに」を表示）と `/manual/:section`（節の ID）。存在しない節は `/manual` に戻す。旧 URL の `/manual#data-import` は `/manual/data-import` に転送する。サイドメニューの「操作マニュアル」は、節のページでも選択中にする。
- `ManualPage.vue` の各節を、節ごとのコンポーネントに分ける。章・節の並び、短い名前、使える権限は 1 か所のデータで持つ（目次、前後の節、検索で共有する）。
- PC：左に章ごとの目次（いまの節を強調）、中央に本文（幅 760px まで）、右に「このページの内容」（小見出しへのリンク。スクロールに合わせていまの小見出しを強調）と関連リンク。本文の最後に「前へ／次へ」を置く。
- スマホ：上部に「章 › 節　目次 ▾」のバーを置き、押すと目次が開く。右の列は出さない。
- この段階では、本文の見た目は今のままでよい。

**実装状況（2026-10-20）:** 実装済み。章・節・小見出しのデータは `resources/js/constants/manual.ts`、各節の本文は `resources/js/components/manual/sections/` に分けた（本文の文言は変えていない）。右の列（「このページの内容」と関連する節）は画面幅が 1536px 以上のときだけ出し、それより狭いときは、左の目次のいまの節の下に小見出しを並べ、関連する節を本文の下に置く。小見出しには ID を付け、`/manual/<節>#<小見出し>` で直接開ける。

### MANUI-02 本文の部品を B 案の見た目にする

- 節の頭：章名、見出し（h1）、権限の札、リード文、「この節の要点」（✓ 付きで 2〜3 行。全節分を書く）。
- 小見出し（h2）を太い下線で区切る。手順は番号を線でつないだタイムラインにする。
- ボタン名・メニュー名の札（メニュー／主ボタン／通常ボタンの 3 種）と、「結果：」の緑の帯を部品にし、全節の本文で使う。
- 注意の囲みを B 案の形にする。取込の失敗は「表示されるメッセージ → どうするか」の対応表にする。
- 右の列に、その節で説明している画面を開くボタン（例：「データ取込画面を開く」）を置く。権限で開けない画面のボタンは出さない。

**実装状況（2026-10-20）:** 実装済み。節の見出しを h1、小見出しを h2、手順の見出しを h3 にした。要点は `constants/manual.ts` の `points`、画面を開くボタンは `screen` に持つ（右の列がない画面幅では、本文の下の関連する節の横に出す）。ボタン名・メニュー名の札（`ManualUi`）は、このアプリの画面の操作だけに付け、BOSS・ターコイズの手順には付けていない。データ取込に小見出し「手順」、品番グループに「グループを作成・編集する」を足した。再照合の手順 1 の見出しは、本文と重ならないよう「差異照合メニューを開きます。」にした。

### MANUI-03 入口ページ（A 案）

- 黒地の見出しに検索欄（検索の動作は MANUI-04）と、よく見られる項目へのリンクを置く。
- 「あなたの権限」：ログイン中のユーザーの権限と、「権限ごとにできること」へのリンク。
- 「1日の流れ」の 4 枚のカード、「やりたいことから探す」の 6 枚のカード（権限の札付き）、「画面の表示の意味」の早見表（—、0、取込待ちの札、ランプの色）。

**実装状況（2026-10-20）:** 実装済み。`/manual` は入口ページ（`components/manual/ManualHome.vue`）を表示し、存在しない節も入口ページに戻す。入口ページから注意の囲みへ直接リンクできるよう、囲みに ID を付けた（`import-errors`・`pending-vs-zero`・`file-retention`・`crosswalker`）。節のページの目次の先頭に「マニュアルのホーム」を置いた。検索欄は置いただけで、動作は MANUI-04 で付ける。

### MANUI-04 検索

- 検索の対象：節の名前、小見出し、要点、節ごとに付けるキーワード（例：「取込待ち」「再照合」「APIキー」）。本文の全文は対象にしない。
- 入口ページの検索欄と、節のページの上部の検索欄から使う。入力するとすぐに候補を出し、選ぶとその節（該当する小見出しがあればその位置）を開く。キーボードの「/」で検索欄に移り、上下キーで候補を選べるようにする。
- 該当がないときは「見つかりませんでした」と、ホームへのリンクを出す。

**実装状況（2026-10-20）:** 実装済み。検索の処理は `resources/js/utils/manualSearch.ts`（全角・半角、大文字・小文字、カタカナ・ひらがな、空白の違いを無視し、空白で区切った語はすべて含むものだけを返す。節名・小見出し ＞ キーワード ＞ 要点 ＞ 説明の順に重く数え、上位 8 件）。キーワードと、小見出し以外に直接開ける場所（注意の囲み）は `constants/manual.ts` の `keywords`・`anchors` に持つ。検索欄は入口ページの見出しと、節のページの目次の上（スマホでは本文の上）に置いた。

### MANUI-05 画面の部分的な再現図

- 次の 4 か所に限って入れる。データ取込の「ファイルを添付」の枠、データ取込画面の「Amazon 在庫」欄（状態と「Amazon 在庫を取得」）、在庫調査結果の上部のボタン（再読込・保存ファイルで再照合・Excel出力）、在庫推移の「日次在庫をCSV出力」のメニュー。
- 実物の画面の部品は使わず、マニュアル用に簡略化した図にする。押す場所は黄色の枠で示す。

## 共通の完了条件

- 画面名・ボタン名・表示文言を、該当する画面のコードと照合して一致させる。
- マニュアルのテスト（`ManualPage.test.ts`、MANUI で分けたあとは各テスト）を変更に合わせて更新し、`npm run check` と `npm run build` が通る。
- 1 チケット＝1 コミットとし、チケットごとに依頼者が内容を確認する。
